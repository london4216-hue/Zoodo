# ZOO — 18 Isolated Companies, One Autonomous Control Plane
Status: OWNER-APPROVED ARCHITECTURAL INTENT — 2026-10-29
Ownership clarification: All 18 repository-backed company projects belong to the same owner. 'Companies' names the owner's distinct company/project environments, not unrelated third-party businesses.
Classification: Patent-candidate concept record, not a patent filing or legal determination.

## Exact plan — non-drift contract
**ONE ZOO autonomous control plane supervising ALL 18 owner-controlled GitHub repositories as 18 individually isolated companies.** Do not select only one company. Do not merge the 18 application codebases. Do not substitute toy demonstrations for real asset evidence. Every repo retains its own code, dependencies, tests, constitution, governance, scorecard, and permissions.

### Control plane
ZOO centrally manages: owner ticket backlog and prioritization; autonomous builders, repairers, reviewers, judges and recovery agents; independent-provider exact-commit verification; bounded failover on non-choice/refusal/tool failure; dependency tracking; fixed-task cross-role benchmarks; timestamped per-agent/tool cost/speed/quality/recovery and claim-vs-proof evidence; shared learning and reusable fix candidates.

### 18 isolated company environments
Inventory all 18 actual connected repositories with stable repository identity, branch/commit baseline, governance/constitution, tests, dependencies, scorecard, UI/UX and relevant asset pillars. Create independently isolated nonproduction fixtures/worktrees/branches, with no cross-lab write access by default. Never read/copy secrets. The original governed TransendIQ and other originals remain intact. The workspace repo Zoodo may host the engine named **ZOO**; the old repo name is not the architecture name.

### Continuous cycle — every hour
1. Keep completing actual owner tickets and ZOO plumbing/dependency work, not only reporting.
2. Collect verified issues, defects, CI/test results, code fixes, scorecard deltas, agent lessons (including Claude) and other evidence from all 18 assets.
3. Run fixed comparable tasks across eligible providers/agents, rotating builder, fixer, reviewer, judge and recovery roles; independently grade outcomes.
4. Execute isolated lab fixes; identify which fixes might transfer across assets; test applicability separately under each lab's governance.
5. Compare actual per-asset before/after scores (including declines), evidence, speed, spend, regressions, quality, recovery and agent false-green claims. Never manufacture improvements.
6. Promote only independently verified, authorized changes to original assets; otherwise keep proposals in the lab.
7. Update durable longitudinal scorecards, lessons and ticket/dependency queues, then repeat.

### Non-choice and anti-regression
No agent refusal, indecision or tool failure may silently stop the control plane. Choose a safe authorized alternate route, bounded retry, different provider, decomposition, or advance another ticket; record recovery evidence. Never bypass access controls, secrets restrictions, independent approval, or safety limits. Prevent regression by running existing tests and comparing verified evidence; if an actual score falls, record it and prioritize repair, not concealment.

### Reporting contract
ONLY (1) integrated autonomy and 18-asset scorecards with baseline/current/delta and evidence, (2) outstanding tickets, dependencies and completed verified fixes, (3) timestamped throughput/lead-time/recovery/cost KPIs, and (4) per-agent/provider/model/tool role scores, Claude lessons, and claim-vs-proof. Unknown is unknown. No claims of clones, live runs, PRs, merges, scores or autonomous operation without receipts.

### Acceptance
ZOO is not autonomous merely because an hourly task runs. Require observed unattended ticket -> real builder -> independent provider exact-commit review -> tested PR -> authorized merge -> durable evidence -> next ticket, repeated across isolated company environments. Original governance and the real UI/UX/assets/17 pillars remain release gates. Do not declare anything shipment-ready based on simulations.
