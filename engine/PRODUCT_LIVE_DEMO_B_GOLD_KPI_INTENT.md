# ZOO — Owner Product Readiness KPI Contract
Recorded 2026-10-29. Mandatory priority before shipping TranscendIQ.

## Owner's objective
For **My Block, YB3, Movement**, and every other owner-controlled asset, first reconstruct a FULL LIVE DEMO from actual intent documents, Figma UI/UX baselines, workflows, dependencies and working code. Next independently score the real demo at **B or better**, then use Zoo to automate fixes and raise legacy and new products to the original **Gold Standard before shipment**. TranscendIQ does not ship until the engine's independent automation, evidence and product standards are proven. Never treat a demo, a B, and Gold as interchangeable.

## Per-asset KPI columns (mandatory)
- Asset name and verified source repository/branch (unknown mappings stay unknown)
- Type: legacy / new / unknown
- Intent/spec inventory completeness %
- Figma/UI/UX baseline coverage %
- Full live demo completion % **verified against explicit required journeys**
- Functional workflow/test completion %
- Dependency readiness %
- Governance/17-pillar evidence coverage %
- Overall verified readiness % (only calculate after documented weighting and denominator)
- Independently assessed grade (unknown, below B, B, B+, A, Gold, etc. using actual rubric)
- B-or-better gate: PASS / FAIL / NOT TESTED
- Gold-before-ship gate: PASS / FAIL / NOT TESTED
- Measured hours and AI dollars to demo, B, Gold; task throughput; mean repair time
- Timestamped proof: exact commit, deployed demo URL, test logs, evaluator, Figma comparison and scorecard
- Remaining tickets, blockers, dependencies, and owner-approved next action

**No invented percentages.** Unknown must be shown as unknown until scope, denominator, and verified work are established. Count only tested features and documented evidence, not agent assertions. Scores can decrease when evidence warrants.
